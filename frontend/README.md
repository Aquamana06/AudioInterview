# Web UI

    npm install
    npm run dev

開発時は Vite が `/api` を `http://127.0.0.1:8000` の Python API に転送します。API を起動するには `../backend/README.md` を参照してください。

回答はテキスト・音声のどちらでも入力できます。

対象者向けの「操作マニュアル」を「設定・履歴」の横から開けます。会話・入力途中の文章を保持し、確認中は録音と読み上げを一時停止します。初回インタビュー前だけ自動表示し、確認済み状態はアカウントごとにサーバーへ保存します。[配布用PDF](public/manual/interview-manual.pdf) と [更新・撮影方法](../docs/operation-manual/README.md) も用意しています。

- テキスト: 入力欄に回答し、「送信」または Enter で送信します。Shift+Enter は改行、IME 変換中の Enter は確定に使えます。マイク権限は不要です。
- 音声: 「音声で回答する」を押すとマイク録音を開始します。「録音中（停止して送信）」を押すか、回答の最後に「どうぞ」または「オーバー」と話すと音声回答を送信します。
- 録音中・音声認識中に入力欄を選ぶとテキスト入力へ切り替わり、その音声回答は送信しません。

管理者（初期ID / パスワード: admin / admin）は従来どおりログイン後に管理画面を表示します。それ以外のアカウントはIDだけでログインでき、そのままインタビュー画面で待機します。新しくIDでログインした場合は待受状態になります。同じブラウザ・同じURLで再読み込みした場合は、有効なログインCookieを使い、開いていたセッション・言語・音声回答の設定を復元します。会話と進行状態はサーバーから読み直します。録音途中の未送信音声は再読み込みで保持されません。「ヘイウィスパー」（Hey Whisper）と呼びかけるか、「インタビューを開始」を押して開始できます。呼びかけで開始した場合は、最初の質問の読み上げ後に自動で音声回答の録音を始めます。開始ボタンを使った場合は、これまでどおりテキスト入力または「音声で回答する」を利用できます。

自動終了・「インタビューを終了」ボタンのどちらでも、固定の「ありがとうございました。これでインタビューを終了します。」を表示・読み上げてから、同じ画面内に記録中の案内を表示します。読み上げが使えない場合もメッセージの表示完了を待ちます。終了メッセージを境界として、開始から終了までを個別のセッションIDで記録します。記録完了後は同じ画面で再び呼びかけを待ち、次のインタビューを開始できます。記録中は重複開始を防ぎ、再読み込み後も記録完了待ちを再開します。要約生成に失敗した場合は保存済みの発話抜粋を記録として保持します。履歴から終了済みセッションを開いた場合は「待受に戻る」を利用できます。

新しいインタビューの準備中も開始ボタンを無効にし、連打による重複作成を防ぎます。最初の質問の生成に失敗した場合、再試行では作成済みの同じセッションを使用します。

インタビュー中の回答の音声認識はバックエンドの `POST /api/speech/transcribe` で行います。ブラウザはマイク録音と音声の送信を担当し、WebGPU やモデルのダウンロードは不要です。「どうぞ」「オーバー」による自動停止も、短い音声をAPIへ送って判定します。

待機中の呼びかけ検出にはブラウザの Web Speech API（SpeechRecognition / webkitSpeechRecognition）を使います。マイク許可と対応ブラウザが必要です。ブラウザによっては認識サービスへ音声が送信されます。認識が自動で止まった場合は再開を試み、権限拒否やエラーの場合は画面に再開ボタンを表示します。非対応の場合も開始ボタンとテキスト入力を利用できます。インタビュー中・記録中は呼びかけ検出を停止し、質問の読み上げによる重複開始を防ぎます。

接続・復元に失敗した場合は、ログイン確認・セッション一覧・記録状況の読み取りを10秒でタイムアウトさせ、再確認の操作を表示します。通信失敗ではログイン情報を消去しません。記録確認中に認証が切れた場合はログイン状態を再確認し、存在しないセッションを参照していた場合は一覧から状態を復元します。
