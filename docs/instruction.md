# 仕様設計書

## 目的

gptのモデルベースのインタビューモデルはできていて，それをグローバル拠点の化学プラントでのリアルタイム音声インタビューシステムとして作るために，データベースとバックエンドとフロントエンドをつないでシステムとして実装したい．

## 実現したいこと

音声入力ができる，テキスト入力ができる，多国語対応，過去の対話履歴を参照して新しいセッションの対話ができる，イヤホンなしでもアリでも，ハンズフリーの音声モードとテキスト入力による音無モードの切り替え可能

## 入力

音声入力：インタビュアの”hey, whisper”，音声入力後，"over"で入力を終了
文字入力：テキストボックスを押して文字列を入力，送信ボタンで終了

## 出力

インタビューエージェントによる出力のテキストおよび読み上げ音声

## 画面・UI要件

システムの応答する言語切り替え可能（日本語・英語・ドイツ語）
テキストボックスをクリックしたら音声入力を終了
hey, whisperと聞き取った際にポーンと音声フィードバック
overと聞き取った際にもポロロロんと音声フィードバック
インタビュアー（システム側）とインタビュイ（オペレータ）のアイコン
UIのベースはAssistant UI

## 機能要件

開始条件：
音声入力の時：インタビュアの”hey, whisper”
文字入力の時：テキストボックスを押して文字列を入力
音声入力中でもテキストボックスクリックで強制切り替え可能
入力ずみでpostしたユーザ入力も後から編集可能・編集時に再度その時点からpost

終了条件：
システム側の「ありがとうございました」(言語ごとに切り替える)，もしくはインタビュー終了ボタンを押すというインタビュイの操作による1セッションの終了

発話終了条件：
音声入力の場合：over
テキスト入力の場合：送信ボタン

音声入力で始まった場合はシステム側も音声読み上げとテキストで出力，テキストの場合は読み上げなしでテキストのみで出力
対話履歴はテキストベースで残る＝普通のchatgptなどと同様
セッションも自由に追加可能＝普通のchatgptなどと同様

## 実装方針の希望

なるべく簡潔に.
アルゴリズムは関数ごとに分け，ファイルもなるべくまとめる
保守運用がしやすいようにモジュール分割をし，適度な疎結合にする
API料金節約のためhey,wisperはブラウザの機能で認識して，ポーンとか音が鳴って，その後にrealtime apiに音声認識を切り替え

## 注意事項

インタビューエージェントのアルゴリズムはtsで書き直すが，その際にagent_framework.md記載のアルゴリズムおよびプロンプトは一切変えないこと．
cloudflareを使用する．
open aiは5.5とウィスパーを使用する
DBはcloudflare D1
frontはcloudflare pages
backendはcloudflare workers
ログイン機能をつけること．ログイン方法はidを打ち込むかQRコードを読み取るかの二択

全てのインタビュー履歴を見れて，かつアカウント発行（id発行）が可能なadminユーザを作成して．adminユーザはid, passwordが必要で，初期はadminとadmin. そのあとは変更可能なようにして．
openai api keyは.envにある．
既存コードで不要なものは削除していいよ．
